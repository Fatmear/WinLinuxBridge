# WinLinuxBridge v1.4.0

发布日期：2026-11-01。重点：事件驱动任务、可见的安装进度、实时日志与后台静默运行。

## 1.4.0 同版本重发修复（2026-11-01）

本次替换 `v1.4.0` 的发布附件，版本号和压缩包名不变，SHA-256 会更新。
首次发布包仍有以下问题，已根据实际安装日志修复：

- 补齐“安装显示 Done，但界面按钮一直点不了”的收尾修复：常驻监督程序继承了安装器输出管道，原先等待 EOF 的逻辑不能结束。现在独立等待安装器本身退出，再取消本次命令的阻塞读取并排空尾部日志，不会停止已经启动的监督程序、代理或隧道。
- 监督程序启动时显式将标准输入输出与安装器分离，并关闭其他继承句柄，继续禁止控制台创建；持久化日志仍实时进入 GUI。实际启动代码使用临时守护验证无控制台及安装器退出后仍能写日志，避免关闭安装管道反过来影响后台桥接。
- 安装、更新、停止任务的按钮解锁和状态显示统一通过 GUI 主线程消息队列执行；配置与密码在主线程读取为本次操作快照，状态刷新不再在后台线程直接访问 Tk 控件，重复刷新合并为一个在途请求。
- 真实 GUI 回归覆盖实际按钮点击、常驻测试子进程仍存活时解锁、实时及尾部日志、安装期间界面响应、连续再次点击，以及非零退出、超时和异常后的解锁；确认日志读取线程不会残留。文件日志通知也验证写入端关闭前可见及停止事件能立即唤醒等待。
- 补充修复安装日志已经输出 `== Done`、界面进度仍停在 **94%** 的问题：现在收到精确完成标记就立即更新为 **100% / 部署完成**，不再等待安装器进程退出或输出管道关闭；进程退出后的失败判定仍保留，普通 `done` 日志不会误触发完成。
- GUI 自测包含进度、完成后的交互和后台收尾回归，控件自测从 14 项增至 **62 项**。
- 正常客户端断连引发的 `ConnectionResetError`（WinError 10054）和 `BrokenPipeError` 被 HTTP 服务打印成异常栈。现在只记录调试信息，不影响代理存活或任务状态；真正的处理异常仍保留错误栈。
- 看门狗使用嵌套命令行引号注册，失败原因不明确。现在使用结构化 ScheduledTasks API，动作执行 `wscript.exe`，参数独立传入 VBS 路径，使用当前登录用户与最低权限。
- 首次镜像刷新前可能只有旧 `.cmd` 入口；注册失败后又因镜像路径没变化而不再重试。现在按 VBS 是否存在选择回退入口，并在镜像刷新后无条件重新注册登录启动项与看门狗。
- 注册权限不足或其他错误会打印具体原因，不会申请管理员权限、索取系统密码或静默假报成功。权限失败时必须按诊断处理旧计划任务，不能承诺旧 `.cmd` 动作已迁移。
- 验收增加真实 TCP 重置、响应写入断连、意外异常仍可见、任务定义/权限/周期、失败诊断以及镜像后重试检查，共 **44 项**。
- 计划任务测试显式预加载模块并检查模拟函数已生效，避免自动模块加载覆盖模拟后误操作真实任务；测试结束恢复原函数。
- 首次发布 ZIP 与校验记录保留本机备份；其他版本的 Release 不删除或覆盖。已经下载首次 `1.4.0` 的用户应重新下载完整 ZIP 并按新校验清单核对。

## 下载与安装

- 下载本 Release 附件 `WinLinuxBridge-1.4.0.zip` 和 `SHA256SUMS.txt`。
- 使用完整发布包，不要使用 GitHub 自动生成的 Source code 压缩包：后者不含便携运行时和供应商二进制。
- Windows 完整解压后，双击 `win\start-gui.vbs` 打开控制面板，不启动命令行窗口。
- 填写 Linux SSH 信息，确认主机指纹，点击「安装并启动」。安装器可自动上传交付目录。
- Linux 交付目录放在 SSH 登录用户的家目录 `~/WinLinuxBridge` 即可，不是系统 `/root`，不需要 root。
- 如果手动解压到 Linux，在用户家目录执行 `unzip WinLinuxBridge-1.4.0.zip`，得到 `~/WinLinuxBridge`。
- Windows 不需要安装 Python、pip 或 PuTTY，不需要管理员权限；仍需要系统 OpenSSH 客户端。

Windows 校验压缩包：

```powershell
Get-FileHash .\WinLinuxBridge-1.4.0.zip -Algorithm SHA256
```

Linux 校验与完整解压：

```bash
sha256sum -c SHA256SUMS.txt
unzip WinLinuxBridge-1.4.0.zip -d ~
```

## 界面与日志优化

- 安装、更新和验证命令的输出逐行进入软件日志面板，标准错误也会捕获，不再依赖单独的 CMD 窗口查看输出。
- 安装显示实际阶段名称、百分比与进度条；这些百分比对应安装步骤，不是文件字节传输进度或耗时预测。
- 后台监督程序、SSH 隧道和代理的日志通过 Windows 文件系统变更通知跟随，新增内容实时进入界面。
- 使用文件系统变更通知和 `WaitForMultipleObjects` 等事件机制，不再为日志增长反复读取整份文件；停止事件可以唤醒等待并释放通知句柄，日志仍落在用户状态目录，关闭界面后可排查。
- 后台进程输出异步复制到可共享读取的日志文件，并在进程结束后释放进程和日志句柄，避免堵塞管道。

## 后台静默运行修复

- 新增 `win\start-gui.vbs`：直接调用便携 `pythonw.exe`，作为默认图形启动入口。
- 新增 `win\start-win.vbs`：无可见命令行窗口地启动后台监督程序。
- 安装器注册的登录启动项改为 VBS，并移除旧的 `WinLinuxBridge.cmd` 启动项。
- 五分钟看门狗改为 `wscript.exe //B //Nologo` 调用 VBS，不再周期性启动 `.cmd`。
- 远端健康检查、SSH/SCP 同步、主机密钥探测、密钥生成、令牌文件 ACL 设置及安装刷新使用 `CreateNoWindow=true`。
- 监督程序启动 Python 代理与 SSH 隧道同样显式禁止创建控制台，而不是创建窗口后再隐藏。
- GUI 启动监督程序不再混用 `CREATE_NO_WINDOW` 与会使其失效的 `DETACHED_PROCESS`。
- 生成的登录启动 VBS 使用 UTF-16，支持中文用户名和安装路径。
- 旧 `.cmd` 文件只保留作手动兼容/诊断入口。Windows 双击 `.cmd` 本身就会启动命令解释器，不能承诺该入口不闪窗；请改用 `.vbs`。
- 本修复针对桥接软件自身的后台启动，不会阻止用户明确执行的图形程序显示窗口，也不改变第三方程序主动启动窗口的行为。

## 任务等待与事件通知优化

- 任务状态优先从受锁保护的内存记录返回，磁盘仍用于持久化与重启恢复，不再靠高频读取 `job.json` 判断变化。
- 状态与终态等待使用条件变量，任务发生有效变化时通知等待者。
- 进程退出由阻塞式操作系统等待发现，再设置完成事件，替代固定 150 毫秒轮询。
- 兼容 `/run` 与任务 API 共用终态等待机制，不维护第二条执行路径。
- Linux 同步命令后续查询采用长轮询，默认等待窗口 `WL_STATUS_WAIT=15` 秒，取代此前每两秒睡眠查询。
- 长轮询窗口是单次等待上限，不表示完成后必须额外等满这个窗口；有状态变化即可返回。
- 必要的心跳、执行超时和输出大小上限检查仍周期执行；目录同步和界面健康刷新也仍保留周期机制。本版本不声称整个系统已无任何轮询。

## 元数据写入优化与准确性

- 非关键心跳先更新内存并标脏，通过事件唤醒后台写入线程，合并多次更新。
- `WL_META_FLUSH_S` 默认 2 秒，可配置为 1–5 秒；`WL_JOB_HEARTBEAT_S` 默认 1 秒，也限制在 1–5 秒。
- 合并的心跳写入仍原子替换文件，但不对每次心跳强制 `fsync`。
- 任务身份、关键状态迁移、PID、退出码、取消意图、最终结果等关键变化仍执行原子且持久化的写入。
- 合并写入与关键变化由同一把锁串行化，避免旧心跳快照覆盖已完成的任务状态。
- 正常关闭任务管理器会唤醒并关闭写入线程，提交剩余脏记录。
- 非关键心跳可能在突发断电时丢失最近一次合并窗口的更新；这一取舍不取消任务身份、终态和去重记录的持久化要求。

## 短任务减少网络往返

- `/job/start` 新增可选的有限等待窗口，短任务完成时直接返回 `completed=true` 和结果。
- Linux 同步 `wl run` 默认在启动请求里等待最多 `WL_START_WAIT=8` 秒；代理端 `WL_START_WAIT_MAX` 默认最多允许 30 秒。
- 窗口内完成的短任务不再必须经历完整的「启动 → 查询状态 → 获取结果」三次调用。
- 超过窗口的任务仍返回持久化任务标识，客户端继续长轮询跟踪，不会重新执行任务。
- `request_id` 去重、断线后的结果查询、资源键串行化和取消隔离保持不变。
- 结构化 `--exe` 与参数列表仍是避免 PowerShell/cmd 启动和多层引号开销的推荐执行方式；原有 shell 用法继续兼容。

## 毫秒级阶段计时

- 新增请求解析、命令准备、队列等待、进程创建、进程运行、完成检测、元数据写入、结果组装和总耗时等阶段数据。
- 使用单调高精度时钟计算阶段耗时，以毫秒返回，便于区分磁盘、网络、排队和 shell 开销。
- `/doctor` 报告当前代理版本、短任务等待上限、心跳及元数据合并写入参数，便于核对实际运行配置。
- 未进行跨设备的前后对照性能基准，因此不声称固定提速倍数；实际收益取决于任务、存储和隧道延迟。

## 稳定性修复

- 补齐 `JobManager` 缺失的后台合并写入、缓存和计时方法，以及缺失的持久化常量，修复代理初始化直接崩溃。
- 修复取消与进程退出事件竞态导致任务错误标为 `FAILED`；取消意图先持久化，再终止目标进程树。
- 保持取消限定在当前任务的进程树，不影响相邻任务、桥接代理或 SSH 隧道。
- 安装器在代理无响应或 Linux 到 Windows 的端到端检查失败时返回失败，不再打印误导性的部署成功。
- 远端执行与安装刷新提供明确的超时/非零退出结果，失败信息进入日志。

## 升级说明

1. 下载并完整解压 `1.4.0`，保留用户目录中的 `.winlinuxbridge` 状态和 `.ssh` 密钥，不要删除任务记录或令牌。
2. 双击 `win\start-gui.vbs`，重新执行「安装并启动」以刷新程序、自启动记录和看门狗入口。
3. 已配置密钥时，可运行下列命令重用密钥；它仍会上传新版程序并刷新启动记录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File win\install-win.ps1 -NonInteractive -SkipKeys
```

4. 单独更新文件不会自动改写旧计划任务。若只是复制新版程序，仍可能由旧 `.cmd` 看门狗启动；必须刷新启动记录。
5. Linux 重新打开 shell 后执行 `wl ping` 和 `wl doctor`，确认实际运行代理为 `1.4.0`，而不仅是目录中的版本文件变更。

## 已知限制

- 截图与桌面控制依赖已登录、未锁定的 Windows 交互会话。
- 登录自启动需要用户登录；看门狗注册权限不足时安装器会明确提示，登录启动项仍可使用。
- Windows Script Host 被组织策略禁用时，VBS 入口无法运行；可直接打开 `win\WinBridgeGUI.pyw` 并选择包内 `pythonw.exe`，不要改用会闪窗的 `.cmd`。
- 自动同步仍是周期扫描，较大文件推荐使用显式 `wl put` / `wl get`。
- 客户端等待超时不等于任务执行失败；仍应按持久化任务标识继续查询。
